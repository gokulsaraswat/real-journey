# Contributing to Real Journey

## Core rule
Main branch owns architecture, naming rules, shared contracts, and merge order.
Feature branches own isolated implementation.

## Good branch examples
- feature/blog
- feature/reader
- feature/feedback-contribute
- fix/story-download-copy

## Before opening a pull request
1. Keep the file surface focused.
2. Mention route paths and admin pages affected.
3. Call out migrations, storage changes, or env changes.
4. Keep private story material out of public issues.

## Feedback lanes
- GitHub issues for public bugs and feature requests
- Email for private notes or quick feedback
- Pull requests for actual implementation
